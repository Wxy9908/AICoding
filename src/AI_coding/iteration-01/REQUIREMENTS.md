# AI Coding 考核题目 · 商品管理后台

> 来源：[http://124.220.100.224/](http://124.220.100.224/) · 考核版本 v1.0  
> 时长：30–40 分钟 · 角色：前端开发（中级/高级）

---

## 1. 项目背景

开发一个**商品管理后台**的完整前端模块，帮助运营人员高效管理商品信息。该页面需具备商品列表展示、新增/编辑商品、上下架控制、批量操作、多条件筛选及分页能力，并严格按照业务规则校验（例如**有库存的商品不允许下架**）。

**提示**：实现完整的前端功能，使用 Mock 接口模拟数据交互，并保证刷新后数据持久化（localStorage）。

## 3. 功能需求

### 3.1 商品列表 & 筛选

- **列表渲染**：展示所有商品，支持分页（每页 5 条），数据来源于前端 mock 或 localStorage。
- **筛选组合**：商品名称（模糊匹配）、状态、分类可独立或组合筛选；筛选后自动重置到第一页。
- **数据持久化**：页面刷新后，所有商品数据、增删改结果必须保留（localStorage 存储）。

### 3.2 新增 / 编辑商品（弹窗表单）

点击「新增商品」打开模态框，表单字段：**商品名称**、**价格**、**库存**、**分类**、**状态**。

**表单校验规则**：

| 字段 | 规则 |
|------|------|
| 商品名称 | 必填，长度 2–20 字符 |
| 价格 | 必填，大于 0 的数字，支持两位小数 |
| 库存 | 必填，非负整数 |
| 分类 | 手机 / 电脑 / 配件（默认手机） |
| 状态 | 上架 / 下架 |

- 编辑时弹窗自动回填数据，保存后更新列表并关闭弹窗。
- 新增商品 id 自动生成（时间戳或递增），添加到列表顶部。

### 3.3 单条上下架 & 业务规则

- 表格操作栏包含「上架」或「下架」按钮（根据当前状态动态显示）。
- **核心规则：库存 > 0 的商品不允许下架。** 若尝试下架且库存 > 0，弹出警告：「库存为 X 的商品不能下架，请先调整库存」。
- 上架操作无需校验库存，直接修改状态为上架。
- 上下架后表格状态实时刷新，数据同步到 localStorage。

### 3.4 批量上架 / 批量下架

- 支持勾选表格中任意商品（复选框），批量操作作用于当前选中的商品。
- **批量下架校验**：若所选商品中存在任意一个库存 > 0，则**整个批量下架失败**，并明确提示「XXX 商品库存不为 0，无法批量下架」。
- 批量上架：直接修改选中商品状态为「上架」。
- 批量操作完成后清空选中状态，重新渲染列表。

### 3.5 编辑与删除

- **编辑**：打开表单弹窗并修改任意字段，保存后更新对应商品信息，遵循相同校验规则（尤其下架时库存校验）。
- **删除**：每一行提供「删除」按钮，点击后弹出确认框，确认后从商品列表中移除（软删除即可）。

## 4. 交互 & UI 细节

| 模块 | 要求 |
|------|------|
| 弹窗表单 | 新增/编辑共用同一组件；提交前校验；错误信息展示在字段下方；成功后关闭弹窗并刷新列表 |
| 状态标签 | 上架绿色背景，下架红色背景；分类用浅色圆角标签 |
| 全选逻辑 | 「全选」仅针对当前页；切换页码后全选重置；手动勾选时全选状态联动 |
| 筛选+搜索 | 点击「搜索」后按名称/状态/分类过滤，重置页码为 1 |
| 分页组件 | 显示当前页/总页数，支持页码点击；数据变化时重新计算分页 |

**加分项（非强制）**：loading 状态、响应式布局、组件划分清晰、代码注释 / AI 使用说明。

## 5. 技术要求 & Mock 说明

| 项 | 要求 |
|----|------|
| 框架 | Vue 3 + Composition API（推荐），必须使用 Pinia / Vuex |
| UI 组件库 | 不限（Element Plus / Ant Design Vue / Vant 或原生），须含模态框、表格、分页 |
| 数据 Mock | 前端模拟增删改查；localStorage 作数据源；封装异步 Promise（如 setTimeout）模拟网络 |
| 构建工具 | Vite 或 Webpack，需可运行 demo |
| 代码风格 | 组件拆分合理，命名语义化，基础可维护性 |
